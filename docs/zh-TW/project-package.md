專案包是包含一趟旅行及其所有媒體的單一檔案，用於備份旅行，並在其他瀏覽器或裝置上還原。

## 1. 檔案

- 副檔名 `.tripreplay`；媒體類型 `application/zip`。
- ZIP 封存檔，項目**不經壓縮直接儲存**，因為照片與影片本身已經過壓縮。壓縮或加密的項目一律拒絕。
- 項目名稱採用 UTF-8。大小於寫入前即已知；CRC-32 值寫在每個項目之後的資料描述區塊中，因此檔案可以串流方式寫入，無須將媒體保留於記憶體。
- 大小或位移達 4 GiB 時使用 ZIP64 紀錄，因此支援超過 4 GiB 的媒體庫。產生的檔案可以一般 ZIP 工具開啟。

## 2. 內容

| 項目 | 內容 |
|---|---|
| `manifest.json` | 專案包中繼資料（如下）；固定為第一個項目 |
| `project.json` | 應用程式所儲存的專案：旅行、景點、片段、素材及音樂 |
| `media/<素材 ID>` | 每個素材的原始檔案，逐位元組相同 |

不允許其他項目。

```json
{
  "format": "tripreplay-project",
  "version": 1,
  "schemaVersion": 1,
  "createdAt": "2026-10-24T08:00:00.000Z",
  "assets": [{ "id": "6f1c…", "path": "media/6f1c…", "byteSize": 2481152 }]
}
```

`version` 為專案包格式的版本；`schemaVersion` 為其中專案資料的版本。

## 3. 讀取與驗證

還原任何內容之前，會先完整檢查專案包。下列情況將拒絕：

- 不是 ZIP 封存檔、檔案不完整，或項目超過 100,000 個、中央目錄大於 32 MiB；
- 項目經壓縮或加密、重複出現，或位於資料區之外；
- 項目名稱不屬於 §2 所列者。因此絕對路徑及 `..` 區段皆不可能出現，素材 ID 也僅限英文字母、數字、`_` 與 `-`；
- `manifest.json` 大於 4 MiB 或 `project.json` 大於 64 MiB，或兩者任一不是有效的 UTF-8 JSON；
- 格式不是 `tripreplay-project`，或 `version`、`schemaVersion` 比應用程式支援的版本新；
- 專案未通過驗證；
- 媒體項目與專案的素材不完全相符，包含大小；
- 還原時媒體檔案的 CRC-32 不符。

## 4. 還原

1. 讀取並驗證專案包（§3）。
2. 若已儲存相同 ID 的旅行，即停止；由使用者決定後續處理方式。應用程式會提供以副本還原的選項，使用新的旅行 ID，並在標題中標示為還原；已以相同 ID 與大小儲存的媒體會共用。
3. 以當機安全的匯入協定（[技術驗證 S6](spikes/s6-web-storage.md)）儲存每個媒體檔案。若已儲存相同素材 ID 且大小相同的檔案，則直接沿用，例如在備份來源的瀏覽器中還原時。
4. 最後才儲存專案，並以從修訂版本 1 開始的新修訂紀錄儲存。

由於專案最後才儲存，還原中斷時只會留下未被任何專案引用的媒體，並由啟動時的復原程序移除。

## 5. 相容性

- 較新的應用程式可讀取所有較早 `version` 與 `schemaVersion` 的專案包，並於結構變更時遷移專案。
- 較舊的應用程式會拒絕無法理解的專案包，而不會只還原一部分。
