# 安全政策

[English](../../SECURITY.md) | 繁體中文

> 本文件為英文版之翻譯；如有歧異，以英文版為準。

## 支援的版本

TripReplay 尚未發行任何版本。開始發行後，僅針對最新版本提供安全性修正。

## 回報弱點

請**勿**透過公開的 Issue、Pull Request 或討論區回報弱點。

請透過 GitHub 私下回報：開啟版本庫的 **Security** 分頁，並選擇 **Report a vulnerability**。回報可使用英文或繁體中文撰寫。

請提供：

- 問題說明及其影響；
- 重現步驟或概念驗證；
- 受影響的平台、版本或 commit；
- 建議的緩解方式（如有）。

請勿於回報中附上您本人的私人照片、影片或旅行資料，請改用範例檔案。

## 範圍

由於 TripReplay 承諾私人資料保留在裝置上（[產品規格 §1.3](specification.md#13-私人資料保留在裝置上之定義)），除一般安全性問題外，下列情況亦視為安全性弱點：

- 任何包含媒體、EXIF 資料、專案內容或本機路徑的遠端請求；
- 啟用離線模式時發出的任何遠端請求；
- 記錄完整本機路徑、EXIF 資料或行程內容的日誌；
- 專案包處理流程允許路徑穿越、解壓縮超量資料，或覆寫應用程式儲存區以外的檔案；
- 在平台提供隔離機制的情況下，離線包或專案資料可被其他應用程式讀取。

## 處理方式

維護者將盡力於 7 日內確認收到回報，並與回報者議定揭露時程。已修正的弱點將透過 GitHub Security Advisories 公開，除回報者另有要求外，將註明回報者的貢獻。
