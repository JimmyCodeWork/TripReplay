## 問題

對固定的時間軸而言，`renderAt(timeUs)` 是否具確定性？包含跨越國際換日線的路線，以及位於相同座標的景點。

## 結果

是。`renderAt` 是僅取決於編譯後時間軸與時間的純函式。測試以 30 fps 渲染每一格畫面兩次，並與另一次獨立編譯的結果比對描述是否相等：鏡頭、路線進度、標記、字幕、媒體狀態及音訊增益皆完全相同。

由於時間軸是不相依平台或地圖的純 TypeScript，原型即依產品標準撰寫，並直接接受為 `packages/timeline`，無須重寫。

## 設計

`compile(project, settings)` 事先解析所有數值；`renderAt(timeline, timeUs)` 只負責查找與內插。

| 步驟 | 決策 |
|---|---|
| 片段 | 開場，接著每個景點依序為移動、景點標題及其片段，最後為結尾。片段首尾相接，因此編輯用的時間軸可將其顯示為一列。沒有片段的景點仍有移動與標題。 |
| 重疊 | 轉場重疊但不改變回顧總長：相鄰的媒體卡片以主題的淡入淡出時間、以交界為中心交叉淡化；景點標籤在該景點所有媒體播放期間持續顯示。 |
| 時長 | 取自主題（開場、移動、標題、結尾、淡入淡出）及片段（照片時長、裁剪後的影片長度）。 |
| 鏡頭 | 每個片段記錄起始與結束鏡頭。移動以 Web Mercator 座標搭配緩入緩出內插；兩端無法同時入鏡時，鏡頭於中途拉遠。`zoom` 以各長寬比的參考畫面尺寸（1920 × 1080 或 1080 × 1920）為準，由渲染器依實際尺寸調整。 |
| 換日線 | 路線經度經展開處理，使每段皆走較短的一側，且可能超出 [-180, 180]（例如從斐濟到薩摩亞為 178.44 → 188.24）。鏡頭與標記使用相同的連續經度。總覽框選展開後路線的範圍，因此路線跨越換日線時總覽亦隨之跨越（於技術驗證 S1 變更；S1 發現只框選景點可能截掉某段路線）。 |
| 相同座標 | 空範圍的適配縮放為無限大，並受最大總覽縮放限制；相同鏡頭之間的移動使鏡頭保持靜止。任何數值皆不會成為 NaN。 |
| 音訊 | 片段聲音跟隨影片位置。音樂於回顧結束處截斷、淡入淡出，並在有聲片段前後以 0.3 秒的漸變降至 25%。 |
| 減少動態效果 | 鏡頭移動改為在中點切換，並以透過地圖背景的淡化（`fade`）遮蔽；照片不推近。 |
| 文字 | 時間軸只攜帶資料（名稱、日期、天數、數量），由呈現層依目前語系格式化。 |

## 測試

| 性質 | 涵蓋方式 |
|---|---|
| 確定性 | 相同時間得到相同畫面，跨編譯亦然；兩次編譯得到相同時間軸；輸入經凍結以偵測變更 |
| 路線單調 | 所有畫面中路線進度皆不倒退 |
| 有效性 | 每格畫面中的每個數值皆為有限值；不透明度維持在 0–1 |
| 換日線 | 向東與向西皆展開為較短路徑；總覽跨越換日線框選；鏡頭連續移動且不經過本初子午線 |
| 相同座標 | 相同景點之間鏡頭靜止；單一景點及沒有景點的旅行 |
| 長距離 | 洲際路段中途拉遠；總覽縮放有效 |
| 音訊 | 片段聲音位置、靜音及無音軌片段、淡入淡出、自動降低音量及其漸變、音樂於結尾截斷 |

破壞較短路徑的展開或圓周總覽後，換日線測試即失敗，證實測試能偵測這些錯誤。

## 待決事項

- 縮放常數（景點縮放 13、最大總覽縮放 11）為初始值，待技術驗證 S1 選定渲染器後以實際圖磚調整。
- 鏡頭路徑採用簡單的拉遠曲線。更平滑的路徑（例如 van Wijk 與 Nuij 的方法）可於 `camera.ts` 內替換，不需變更時間軸格式。
- 各景點的個別縮放與各主題的轉場樣式不在 1.0 範圍內。
