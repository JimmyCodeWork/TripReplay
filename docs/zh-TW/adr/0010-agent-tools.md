# 0010. 透過 WebMCP 為瀏覽器的 AI 代理提供工具

## 背景

維護者希望為電腦版提供 MCP server，讓 AI 代理協助撰寫旅行：規劃景點、撰寫日記與備註，以及調整時間設定。

網頁應用程式將旅行存放在瀏覽器的儲存空間（IndexedDB 與來源私有檔案系統），獨立的 MCP server 程序無法讀取。評估過三種做法：

- **讀寫備份檔的本機 MCP server。** 可離線運作，也不必修改應用程式，但每次變更都需要匯出再還原。
- **由開啟中的應用程式連線的本機 MCP server。** 變更能立即呈現，但應用程式必須建立連線（即使只連到同一台電腦），這違反 [ADR 0006](0006-local-only-operation.md)，且連線需要配對與保護。
- **WebMCP。** 網頁向瀏覽器註冊工具（`document.modelContext.registerTool`，[WebMCP 草案](https://webmachinelearning.github.io/webmcp/)），由瀏覽器內建的代理呼叫。工具在網頁中執行，作用於正在編輯的旅行。

維護者選擇 WebMCP。2026 年 11 月時，它在 Chrome 149 至 156 以來源試用（origin trial）提供，沒有任何瀏覽器預設啟用。Chrome 最初以 `navigator.modelContext` 提供，之後改為 `document.modelContext`。Android System WebView 不提供此功能。

## 決策

1. **僅使用 WebMCP。** 網頁應用程式透過 `document.modelContext` 提供工具；在以 `navigator.modelContext` 提供的瀏覽器中則使用後者。TripReplay 不執行 MCP server，也不建立任何連線；由瀏覽器將代理的呼叫傳給網頁。
2. **預設關閉，由使用者開啟。** 工作區上方的「**AI 代理**」按鈕只在瀏覽器提供 WebMCP 時顯示，用來開啟或關閉工具。此選擇保存在瀏覽器的本機儲存空間。只有在開啟某趟旅行且工具已開啟時，才會提供工具。
3. **僅限開啟中的旅行，且僅限文字。** 一個工具讀取旅行：標題、日期、每日開場文字、景點及其位置與日記，以及照片與影片的檔名、備註與長度。其餘工具可重新命名旅行、新增景點、修改景點（名稱、位置、日記、日期與順序）、設定每日開場文字、設定照片或影片的備註、設定照片秒數，以及設定回顧時間。沒有任何工具會讀取或傳送照片、影片或音樂，也不會刪除任何內容、匯入檔案或開啟其他旅行。
4. **所有變更都經由編輯器。** 工具送出與介面相同的指令，因此每項變更都會經過驗證、自動儲存，且可作為一個步驟復原。輸入錯誤時會拒絕執行，並告知代理應如何修正。
5. **工具定義不依賴 WebMCP。** `app` 套件以 JSON Schema 定義工具，由網頁外殼註冊。日後若以其他方式提供，可沿用相同定義。

## 考慮過的替代方案

- **讀寫備份檔的本機 MCP server。** 未採用：每次變更都需要匯出再還原，而維護者希望直接在開啟中的旅行上操作。
- **由應用程式連線的本機伺服器。** 未採用：會為使用者工作時不連網的應用程式增加網路連線（[ADR 0006](0006-local-only-operation.md)），且需要配對，並防範其他本機程式。
- **刪除景點或媒體、匯入檔案的工具。** 第一版不提供，以免代理造成工作成果遺失，或加入使用者未選擇的檔案。

## 影響

- 開啟工具後，瀏覽器的代理會讀取開啟中旅行的文字（包括景點位置），代理的服務供應商可能因此取得這些內容。[隱私權聲明](../privacy.md)已載明此事。TripReplay 本身仍不傳送任何資料。
- 旅行的文字可能來自他人（例如還原的備份），因此讀取工具會標示其結果包含不受信任的內容。
- WebMCP 仍是草案。這些工具依據 2026 年 11 月的規格實作，並以 `document.modelContext` 的替身進行測試；草案或 Chrome 的變動可能需要隨之調整。
- 瀏覽器可能在工具撤回後仍保留它。因此工具會在被呼叫時才查找開啟中的旅行，並在沒有開啟旅行或工具已關閉時拒絕執行。
- 來源試用期間，只有在網站來源已註冊試用且頁面帶有其權杖，或使用者開啟 `chrome://flags/#enable-webmcp-testing` 時，Chrome 才會在該網站提供 WebMCP。應用程式目前尚未包含任何權杖；為發布的網站註冊權杖由維護者負責。
- Android 應用程式不提供這些工具。
