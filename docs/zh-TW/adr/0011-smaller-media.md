# 0011. 照片與影片的縮小副本

## 背景

TripReplay 會將每張匯入的照片與每段影片以原始檔案儲存，備份也包含相同的檔案，且不另外壓縮（[專案封裝檔 §1](../project-package.md#1-檔案)）。手機照片每張約 3 至 10 MB，因此維護者的旅行僅放兩天的照片就達到約 500 MB。回顧所需遠低於此：預覽解碼照片時長邊最多 1920 像素，匯出的影片最高為 1080p（[ADR 0009](0009-export-in-1-0.md)）。

維護者希望在匯入、備份與匯出影片時都能選擇縮小媒體，照片與影片皆然，並能縮小已匯入旅行的照片。

## 決策

1. **尺寸。** 縮小後的照片長邊最多 2560 像素，約為回顧最大畫面的 1.3 倍，使緩慢推近時仍保持清晰。以品質 0.85 的 JPEG 編碼，所有支援的瀏覽器皆可解碼。
2. **中繼資料。** 拍攝時間與位置一如以往，於匯入時讀取並保存在旅行中。縮小副本會依相機記錄的方向轉正，不保留其他中繼資料。
3. **僅在有效時使用。** 只有比原檔至少小五分之一時才保留副本。瀏覽器無法解碼的照片（例如 Safari 以外的 HEIC）與動態 GIF 維持原樣。
4. **匯入時可選。** 「媒體」分頁中的「**匯入時縮小照片**」核取方塊決定匯入時是否儲存縮小副本。在使用者關閉之前保持開啟，且此選擇會保存在瀏覽器中。資產保留原檔的內容雜湊，因此再次匯入原檔時仍會被辨識為重複。
5. **已匯入的旅行。** 旅行列表中某趟旅行的「**縮小媒體**」會先顯示照片與影片的數量及所占空間並請使用者確認，再將該趟旅行的照片（若有選擇，也包括影片，見 §8）換成縮小副本。此功能作用於未開啟的旅行。每個副本以新的資產 ID 儲存，並只儲存一次旅行，因此中途中斷時旅行不會變更。之後會刪除原檔，但若其他旅行（例如建立的副本）仍在使用則保留。此變更無法在 TripReplay 中復原；介面會提醒使用者，若要保留原尺寸照片，請先備份。
6. **備份時可選。** 「**備份**」會詢問「**原尺寸**」或「**縮小照片**」，並提供「**也縮小影片**」。選擇縮小時，封裝檔以新的資產 ID 保存副本，因此還原到仍保存原尺寸媒體的裝置時兩者都會保留；裝置上的旅行不會變更。副本會在使用者選定儲存位置後才產生，並在備份寫入完成前暫存於媒體儲存空間。
7. **匯出的影片。** 除了 1080p 或 720p，匯出還提供檔案大小選項：較大、標準或較小，即每格每像素每秒 6、4 或 2 位元（1080p 約 12、8 與 4 Mbit/s），並顯示影片的預估大小。
8. **影片。** 縮小後的影片長邊最多 1920 像素，以瀏覽器的 WebCodecs 編碼器重新編碼（能用 H.264 時使用 H.264，否則用 VP9 或 AV1），位元率為每格每像素每秒 3 位元（1080p 約 6 Mbit/s），每 2 秒一個關鍵影格。聲音（AAC 或 Opus）原封不動地複製，並保留相機記錄的旋轉與時間戳，因此裁剪設定仍然有效。由 `mp4box` 2.5.0（BSD-3-Clause）讀取原始的 MP4 或 QuickTime 檔案，`mp4-muxer` 寫入副本。瀏覽器無法解碼的影片（例如沒有硬體支援時的 HEVC）、聲音為其他格式的影片，以及無法至少小五分之一的影片，都維持原樣。重新編碼所需時間約與影片長度相當或更久，因此只在使用者選擇時才縮小影片：「媒體」分頁的「**匯入時縮小影片**」在開啟前保持關閉，縮小旅行與備份時的影片選項亦然。讀取程式只在縮小影片時才載入。

## 考慮過的替代方案

- **壓縮備份。** 單獨使用效果有限：JPEG 與 MP4 本身已是壓縮格式，ZIP 壓縮能省下的很少。
- **以 WebP 或 AVIF 取代 JPEG。** 同樣品質下檔案較小，但各瀏覽器的編碼支援不一，而備份應能在任何地方開啟。JPEG 能讓備份在任何瀏覽器與照片工具中讀取。
- **以影片元素即時播放並擷取來縮小影片。** 不採用：比以 WebCodecs 解碼慢、會掉格，且除非重新錄製，否則會失去聲音。
- **一律縮小。** 不採用：維護者希望可以選擇，且有些使用者希望在 TripReplay 中保留原尺寸照片。

## 影響

- 開啟核取方塊後，以手機照片為主的旅行及其備份只占原本空間的一小部分。
- 縮小照片的備份在寫入時會將副本保留在記憶體中，每張照片約 1 MB；原尺寸備份則是以串流方式寫入已儲存的檔案。
- 以縮小尺寸儲存的照片無法在 TripReplay 中恢復原尺寸；裝置上的原始檔案不受影響。
- 若日後提供 4K 匯出，以縮小尺寸儲存的照片不會因此更清晰。
