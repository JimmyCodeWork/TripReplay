## 背景

[1.0 定義](../release-1.0.md)原將回顧的影片匯出留待 1.0 之後的版本，並以 spike S3 為前提（[開發路線圖 M5](../roadmap.md#m5--匯出階段-d)）。維護者在 Android 上測試時發現，沒有影片檔就無法保存或分享回顧，因此要求在 1.0 提供匯出。

架構已為此預先準備：
- `renderAt(timeUs)` 不必繪製即可描述任一畫面。
- 地圖圖層能以固定像素比繪製到可讀取的畫布，並在畫面完整繪製時通知。
- 聲音的增益與預覽來自相同的畫面描述（[規格 §7](../specification.md#7-預覽與影片處理流程)）。

探測 WebCodecs 的結果：

- Chrome、Edge 與 Android System WebView 可編碼 H.264 影像（手機上使用硬體編碼器），多數系統也可編碼 AAC 聲音。
- 不含專有編碼器的 Chromium 版本（例如自動化測試所用者）只能編碼 VP9 或 AV1 影像，以及 Opus 聲音。
- Firefox 可編碼 VP9、AV1 與 Opus；Safari 可編碼 H.264 與 AAC。

[授權政策](../license-policy.md)將 mp4-muxer 5.2.2（MIT）列為可採用。其作者已以 Mediabunny 取代它，但 Mediabunny 採 MPL-2.0，不得用於發行成品（[ADR 0001](0001-dependency-license-scope.md)）。

## 決策

1. **範圍。** TripReplay 1.0 可將回顧匯出為 MP4 檔：
   - 1080p 或 720p、每秒 30 格，畫面比例與旅行相同；
   - 影片與預覽一樣混入片段聲音與背景音樂；
   - 每一格都繪有地圖資料來源標示。
2. **編碼。** 新套件 `export` 以 WebCodecs 編碼。匯出前會探測編碼器：
   - 影像依序取第一個支援者：H.264 High、H.264 Main、VP9、AV1；
   - 聲音取 AAC，不支援時改用 Opus；
   - 無影像編碼器的環境會告知無法匯出；無聲音編碼器的環境會產生無聲影片並附說明。
3. **MP4 容器。** 由 `mp4-muxer` 5.2.2 寫入檔案。它雖已停止維護，但對此用途功能完整且體積小；版本已固定，並在授權清單中審查。因授權之故不採用 Mediabunny。若 mp4-muxer 無法再使用，專案將自行撰寫 MP4 寫入程式，而不改用 MPL-2.0 的套件。
4. **畫面。** 由 shell 依每個時間點的畫面描述，以輸出尺寸在畫面外繪製：
   - 地圖圖層以像素比 1 繪製，並等待畫面完整繪製；
   - 照片以最長邊 1920 像素解碼；
   - 影片移到該格的時間點。

   每一格編碼後才繪製下一格，編碼器中最多等待四格，因此整段影片不會放在記憶體中。
5. **聲音。** 每 50 毫秒取樣一次畫面描述；各來源以 48 kHz 解碼，並以與預覽相同的增益、淡入淡出與降低音量離線混音，再於畫面之前編碼。
6. **檔案。** MP4 先寫入來源私有檔案系統中的暫存檔。完成後，由使用者要求才儲存：
   - 瀏覽器有儲存對話框時使用該對話框；
   - 否則存到下載資料夾；
   - Android 應用程式中則透過 `SaveFile` 外掛儲存。

   取消、失敗或頁面切到背景時，匯出會停止並刪除暫存檔；殘留的暫存檔會在下次啟動時刪除。
7. **前景。** 依[規格](../specification.md#71-輸入與輸出格式)對行動裝置的要求，匯出只在前景進行；瀏覽器允許時會保持螢幕開啟。

## 考慮過的替代方案

- **維持在 1.0 之後提供匯出。** 如上所述，維護者不採納。
- **Mediabunny。** 不採用：MPL-2.0。
- **WebAssembly 編碼器（例如 FFmpeg）。** 不採用：體積大、在手機上速度慢，且 FFmpeg 常見的建置採 LGPL 或 GPL。
- **以 MediaRecorder 即時錄製預覽。** 不採用：
  - 結果取決於裝置是否跟得上，可能掉格；
  - 格式因瀏覽器而異（常為 WebM）；
  - 錄製時間與回顧一樣長。
- **原生 Android 編碼器外掛。** 延後：Android System WebView 上的 WebCodecs 使用相同的硬體編碼器，一套實作即可同時用於兩種建置。

## 影響

- 1.0 定義、開發路線圖與瀏覽器支援將匯出列為 1.0 的一部分。各瀏覽器的匯出支援不同，對話框會說明將產生的格式。
- 匯出速度取決於裝置：每一格都要等待地圖繪製完成。另提供 720p 供較慢的裝置使用。
- 匯出的檔案由自動化測試在 Chromium 中檢查（VP9 與 Opus），並在 Android 裝置上以人工檢查（H.264 與 AAC）。spike S3 在其他系統上的量測尚待記錄。
- `export` 只依賴 `timeline`；畫面由 shell 提供，因此不需要地圖即可測試此套件。
