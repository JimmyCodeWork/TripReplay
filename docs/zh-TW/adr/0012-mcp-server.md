# 0012. 供 AI 代理使用、依使用者選擇連線的本機 MCP Server

## 背景

[ADR 0010](0010-agent-tools.md) 透過 WebMCP 將開啟中的旅行提供給瀏覽器內建的 AI 代理。2026 年 11 月時，沒有任何瀏覽器預設啟用 WebMCP，而 Claude Desktop 與 Claude Code 等代理已能使用 MCP server 提供的工具。維護者希望提供可開關、預設關閉的 MCP server。

MCP server 是電腦上的程式，而 TripReplay 將旅行存放在瀏覽器的儲存空間，這類程式無法讀取。評估過三種做法：

- **編輯備份檔的 server。** 不需要連線，但每次變更都需要備份再還原。
- **由開啟中的 TripReplay 連線的 server。** 與 WebMCP 一樣直接修改開啟中的旅行，但網頁需要建立連線（僅限同一台電腦）。
- **從外部讀取瀏覽器的儲存檔案。** 直接排除：這依賴瀏覽器的內部格式，且會繞過應用程式。

## 決策

1. **本機 MCP server：`apps/mcp`。** 一支由代理啟動、透過標準輸入與輸出溝通的 Node.js 程式。它只實作工具型 server 所需的 MCP 部分（初始化、列出與呼叫工具），不使用 MCP SDK，因此只多出 `ws`（MIT）一個相依套件。它提供 ADR 0010 的工具（沿用 `app` 套件中的同一份定義），以及 `tripreplay_status` 工具，用來說明 TripReplay 是否已連線及如何連線。
2. **旅行留在瀏覽器中。** server 在 `127.0.0.1:4174` 等待 TripReplay 的 WebSocket 連線，並將每個工具呼叫轉交給它；TripReplay 透過編輯器在開啟中的旅行上執行工具，因此每項變更都會經過驗證、自動儲存，且可作為一個步驟復原，再回傳結果。
3. **預設關閉，由使用者開啟。** 網頁應用程式（不含 Android 應用程式）工作區上方的「**MCP**」按鈕用來開啟或關閉連線，此選擇保存在瀏覽器中。開啟且有旅行開啟時，TripReplay 每隔幾秒尋找一次 server；server 只在代理啟動它時執行。
4. **以配對碼配對。** server 將六位數配對碼保存在使用者的設定目錄中，只有使用者可讀取；TripReplay 未連線時，server 會將配對碼告訴代理，由代理轉告使用者，使用者在該瀏覽器中輸入一次即可。server 會拒絕沒有正確配對碼的連線，也會拒絕專案網站與 `localhost:4173` 上的 TripReplay 以外來源的網頁；可用 `TRIPREPLAY_MCP_ORIGINS` 加入其他來源。同一時間只會連線一個 TripReplay。
5. **網頁只允許這個位址。** 內容安全政策在允許的連線中加入 `ws://127.0.0.1:4174`，除此之外沒有其他變更。

## 考慮過的替代方案

- **MCP SDK。** 不採用：工具型 server 只需要協定的一小部分，而 SDK 會為 stdio server 帶來 HTTP 堆疊與大量需要審查的套件。
- **編輯備份檔的 server。** 未選為第一步：每次變更都需要備份再還原。日後仍可實作。
- **不配對，只依賴來源檢查。** 不採用：電腦上的其他程式可以送出任意來源。配對碼可防止它們操控 TripReplay。

## 影響

- 開啟 MCP 時，代理會讀取開啟中旅行的文字，其服務供應商可能因此取得這些內容，與 WebMCP 相同。[隱私權聲明](../privacy.md)已載明此事。
- 網頁應用程式多了一種連線：只連到自己的電腦，且只在使用者開啟 MCP 時進行。它仍然不會傳送任何資料到其他伺服器。
- 瀏覽器可能會在網站連線到使用者自己的電腦前要求授權，例如 Chrome 的區域網路存取提示。
- 使用 server 需要 Node.js 24 與一份原始碼（可用 `launch/` 中的啟動程式安裝），並在代理的設定中加入一項設定（[使用指南 §5](../user-guide.md#5-寫日記)）。
