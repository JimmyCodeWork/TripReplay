# 0017. 手動檢查更新

## 背景

網頁應用程式會自行更新：其 service worker 會在背景下載網站的新版本，於下次開啟 TripReplay 時生效。使用者無從得知何時更新，也無法要求立即更新。Android 與 Windows 應用程式的檔案都在安裝套件中（[ADR 0008](0008-android-in-1-0.md)、[ADR 0016](0016-windows-application.md)），除非自行前往專案的發行頁面，否則完全無法得知新版本。維護者要求提供手動檢查更新的功能。

## 決策

1. **只在使用者要求時檢查。** 「**設定 → 關於**」顯示根目錄 `package.json` 中的版本，以及「**檢查更新**」。除了瀏覽器本身對 service worker 的檢查之外，不會自動檢查。
2. **網頁應用程式**請 service worker 檢查網站是否有新版本（`ServiceWorkerRegistration.update()`）。新版本開始使用後，或自頁面開啟以來新版本已接手頁面時，TripReplay 會提供「**重新載入**」。
3. **Android 與 Windows 應用程式**向 GitHub 的 API 查詢發行版本清單（`api.github.com/repos/JimmyCodeWork/TripReplay/releases`），並依語意化版本規則將最新版本與自身版本比較（`app` 中的 `newerRelease`）。預先發行版本只會提供給預先發行版本的使用者。有較新版本時提供「**前往下載頁面**」，即該版本的發行頁面，使用者從中下載 APK 或安裝檔並覆蓋安裝舊版。這兩者的內容安全政策允許 `api.github.com`，網頁應用程式則不允許。
4. **不傳送其他資料。** 請求不含任何旅行資料或使用者識別資訊；GitHub 可得知 IP 位址、時間，以及有人進行了檢查。[隱私聲明](../privacy.md)已列出此請求。

## 考慮過的替代方案

- **啟動時自動檢查。** 每次開啟 TripReplay 都會在使用者未操作的情況下向第三方發出請求，這正是 ADR 0006 所避免的。
- **在應用程式內直接安裝更新。** Android 需要安裝套件的權限，Windows 則需要由應用程式下載並以提高權限執行安裝檔；兩者相較於發行頁面，增加的風險多於好處。

## 影響

- 所有版本的使用者都能在需要時找到並取得新版本。
- Android 與 Windows 應用程式多了一個可連線的主機，且只在使用者選取「**檢查更新**」後才會連線。
- 須等以標籤發行版本之後（[發行流程](../releasing.md)），此檢查才有實際用途；在那之前，會顯示尚未發布任何版本。
