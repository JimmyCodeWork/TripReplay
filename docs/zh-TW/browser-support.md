## 1. 支援的瀏覽器

TripReplay 1.0 支援下列瀏覽器的目前版本與前一個主要版本（[1.0 定義 §3](release-1.0.md#3-平台)）。它需要 WebGL 2、IndexedDB 及來源私有檔案系統；缺少這些功能的瀏覽器會顯示說明訊息，而不會開啟應用程式。

| 瀏覽器 | 裝置 | 狀態 |
|---|---|---|
| Chrome | Windows、macOS、Linux、ChromeOS、Android | 支援。自動化瀏覽器測試及每次發行的端對端檢查都在 Chromium 中執行 |
| Edge | Windows、macOS | 支援。使用與 Chrome 相同的引擎 |
| Firefox | Windows、macOS、Linux | 支援目標。尚未納入自動化測試；請見 §3 |
| Safari | macOS、iPadOS、iOS | 支援目標。尚未納入自動化測試；請見 §3。在 iPhone 與 iPad 上，所有瀏覽器都使用 Safari 的引擎，因此 Safari 的說明同樣適用 |

在桌上型與筆記型電腦上能得到最佳體驗。平板與手機可透過其瀏覽器使用；在窄螢幕上，工作區會改為單欄版面。

## 2. 各瀏覽器的差異

| 功能 | Chrome、Edge | Firefox | Safari |
|---|---|---|---|
| 安裝為應用程式 | 網址列中的安裝按鈕或瀏覽器選單 | 桌面版不提供。Android 上請使用瀏覽器的安裝選項（若有） | macOS：「**檔案 → 加入 Dock**」。iPhone 與 iPad：「**分享 → 加入主畫面**」 |
| 儲存備份 | 詢問儲存位置並直接寫入檔案 | 存到下載資料夾 | 存到下載資料夾 |
| 全螢幕播放 | 支援 | 支援 | Mac 與 iPad：支援。iPhone：瀏覽器不允許網頁進入全螢幕；請將手機轉為橫向並使用預覽 |
| HEIC 照片（iPhone 的預設格式） | 無法顯示；請見 §3 | 無法顯示；請見 §3 | 可顯示 |
| HEVC（H.265）影片 | 裝置能解碼 HEVC 時可播放 | 視系統與版本而定 | 支援 |
| 保留已儲存的資料 | 裝置空間不足時，瀏覽器可能清除 | 裝置空間不足時，瀏覽器可能清除 | 一段時間未使用後也可能被清除，除非已將 TripReplay 加入主畫面或 Dock |

## 3. 已知問題

| 問題 | 因應方式 |
|---|---|
| **Firefox 與 Safari 尚未納入自動化測試。** 每次發行時會以人工檢查；若發現任何問題，請回報 | 若功能無法正常運作，請改用 Chrome 或 Edge，並[回報問題](https://github.com/JimmyCodeWork/TripReplay/issues) |
| **瀏覽器可能清除已儲存的資料。** 在所有測試過的裝置上，瀏覽器都未核准 TripReplay 的永久儲存要求。Safari 可能刪除一段時間未使用之網站的資料 | 請備份想保留的旅行（[使用指南 §9](user-guide.md#9-備份與還原)）。在 Safari 中，請將 TripReplay 加入主畫面或 Dock |
| **iPhone 與 iPad 的儲存空間較少。** 在測試的 iPad 上，Safari 為每個網站提供約 1 GB；一個區域的地圖就可能佔用將近一半 | 只下載需要的區域，旅行結束後刪除地圖。每次下載與匯入前，TripReplay 都會確認可用空間 |
| **Safari 以外的瀏覽器無法顯示 HEIC 照片。** 匯入時會標示為「不是此瀏覽器可顯示的照片或影片」 | 請在 Safari 中匯入，或先轉換為 JPEG。在 iPhone 上，「**設定 → 相機 → 格式 → 最相容**」可讓新拍的照片存為 JPEG |
| **在 Firefox 與 Safari 中備份大型旅行**時，備份會先在記憶體中組合再儲存，因此含有數 GB 影片的旅行需要同等大小的可用記憶體 | 請在 Chrome 或 Edge 中備份大型旅行，它們會直接寫入檔案 |
| **地圖短網址**（例如 `maps.app.goo.gl`）必須詢問其服務才能解讀 | 請開啟連結後複製完整連結，或直接貼上座標 |
| **1.0 不提供影片匯出。** 回顧只能在應用程式中播放 | MP4 匯出預計於 1.0 之後提供（[開發路線圖](roadmap.md#10-之後)）。在此之前，請使用全螢幕播放或系統的螢幕錄影功能 |
